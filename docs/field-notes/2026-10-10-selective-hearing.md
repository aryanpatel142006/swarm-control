## ~16:30 UTC · board id race fixed (option b, extended)

What happened: the 03:00 note's race kept firing. T-218, T-221, T-284, T-290 and T-301 each existed twice, and so did Q-594 and Q-641. A runner looked up T-284 by id, got the other page and logged "claim lost" for many minutes. The orchestrator renamed pages by hand (a Cut duplicate's ID set to "T-284-dup-of-T-290"). When this fix was written, `swarm doctor --dupes` showed live task duplicates T-285 (Running claude-a and Ready codex-b), T-305 (one Cut) and T-306 (Failed copilot-b2 and Ready antigravity-b), plus about 35 duplicated question ids.

Fixed:
- `NotionBoard._settle_id` replaces `_dedupe_question_id` and now covers tasks as well. After `create_task`/`create_question` allocates an id, it queries that id up to 3 times, 1 s apart. If another page holds the id and was created earlier (created_time, then page id), our page allocates max+1 again, renames itself (ID plus title) and checks the new id the same way, up to 4 renumbers. Only the page this process created is ever renamed. Notion rounds created_time to the minute, so a same-minute tie goes to the lower page id. The winner waits 3 s once; if the other page still holds the id after that, the winner renames itself too, because the other creator may have finished checking before our page existed. Cost: about 2 s per create. A caller's own id (planner batches, whose dependencies link by id) is never renumbered. `swarm add` prints the final id.
- `get_task(id, page_id=, agent=)`: when several pages share an id, the caller's own page wins. Otherwise Cut pages are ignored while a live one exists, then the page assigned to `agent` wins, then the oldest. A WARNING lists every page, at most once per id per 10 min per process. Claim, claim watch, publish and serve's re-reads pass the task's page_id, so a duplicate can no longer make a runner think its claim was lost.
- `swarm doctor --dupes` lists every id held by more than one page (page id, status, agent or kind, title). `swarm status` adds a RISK line naming the task duplicates first and then up to 5 question ids.

Limits: a create still races when Notion's filtered query takes longer than about 3 s to show the other page. Status and doctor catch what slips through. Laptop-b only self-corrects after it pulls swarm-control. Serve and the runners need a restart (when idle) before the get_task preference applies to them.
